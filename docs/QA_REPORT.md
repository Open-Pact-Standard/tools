## Issues found

### 🔴 CRITICAL — blockers for pilot: **none remaining.**

The one CRITICAL issue found during live use — **clicking a capability did nothing** —
is **FIXED and verified**:

**RF0 (CRITICAL, FIXED): Studio page JS had a syntax error, killing all clicks.**
The adapters page is generated by a Python f-string. Escaped JS newlines inside
single-quoted strings (`join('\n')`, `'\n'+...`) were written with a **single**
backslash in the source; the f-string converted each `\n` into a real newline,
producing an invalid token in the served `<script>`. The browser's parser
discarded the ENTIRE script block on the syntax error, so `openCap`, `runCap`,
`collect` — every click handler — was undefined. That's why clicking a
capability card did nothing.

**Fix:** converted the JS newline escapes in the f-string source to double
backslash (`\\n`), so Python emits `\n` (valid JS). Verified three ways:
- served `<script>` now passes `node --check` (was: invalid or unexpected token)
- the actual click flow executes in a DOM-stubbed eval: `openCap('custom-opl')`
  clears the panel, renders the card + Run button + consequence div + all fields
- regression guard `test_adapters_js_has_no_broken_newlines` added; proven to fail
  on the broken output and pass on the fixed output.

This was caught by a real user clicking the page (you), exactly the live-use signal
no automated gate produced.
